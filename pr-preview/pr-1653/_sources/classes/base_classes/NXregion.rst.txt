.. _NXregion:

========
NXregion
========

**Status**:

  base class, extends :ref:`NXobject`

**Description**:

  .. collapse:: Geometry and logical description of a **R**-dimensional region of data in a pare ...

      Geometry and logical description of a **R**-dimensional region of data in a parent group. When used, it could be a child group to, say, :ref:`NXdetector`.

      This is modelled after the `NDPluginROI <https://areadetector.github.io/areaDetector/ADCore/NDPluginROI.html>`_ and
      `NDPluginROIStat <https://areadetector.github.io/areaDetector/ADCore/NDPluginROIStat.html>`_ plugins
      in the EPICS areaDetector framework and can describe a subset of data used to create downsampled data or to derive some statistics from that subset.

      Note, the fields for the rectangular region specifiers follow HDF5’s dataspace hyperslab parameters
      (see in the HDF5 User Guide, the Hyperslab Selection section of `Dataspaces and Data Transfer <https://support.hdfgroup.org/documentation/hdf5/latest/_h5_s__u_g.html#title4>`_ and
      `Reading From or Writing To a Subset of a Dataset <https://support.hdfgroup.org/documentation/hdf5/latest/_l_b_dset_sub_r_w.html>`_). Note when
      **block** :math:`= 1`, then **stride** :math:`\equiv` **step** in Python slicing.

      For example, a ROI sum of an area starting at index of [20,50] and shape [220,120] in image data::

      	detector:NXdetector/
      		data[60,256,512]
      		region:NXregion/
      			@region_type  = "rectangular"
      			parent = "data"
      			start  = [20,50]
      			count  = [220,120]
      			statistics:NXdata/
      				@signal = "sum"
      				sum[60]

      the ``sum`` dataset contains the summed areas in each frame.
      Another example, a hyperspectral image downsampled 16-fold in energy::

      	main_data:NXdata/
      		@signal = "data"
      		@axes = [".", ".", "energy"]
      		data[128,64,4096]
      		energy[4096]
      		region:NXregion/
      			@region_type  = "rectangular"
      			parent = "data"
      			start  = [2]
      			count  = [20]
      			stride = [32]
      			block  = [16]
      			downsampled:NXdata/
      				@signal = "maximum"
      				@auxiliary_signal = "minimum"
      				@axes = [".", ".", "energy"]
      				maximum[128,64,20]
      				minimum[128,64,20]
      				energy[20]
      			downsampled_copy:NXdata/
      				@signals = "copy"
      				@axes = [".", ".", "energy"]
      				copy[128,64,320]
      				energy[320]

      the ``maximum`` dataset will show maximum values in each 16-channel
      block in every spectra, the ``copy`` dataset selects 20 16-channel
      blocks that start 32 channels apart. Note, the ``copy`` dataset resides
      in a separate :ref:`NXdata` group owing to its shape and ``downsampled_copy/energy``
      dataset will have repeated values.

**Symbols**:

  .. collapse:: These symbols will denote how the shape of the parent group's data field, ...

      These symbols will denote how the shape of the parent group's data field,

      .. math:: (D_0, ..., D_{\mathbf{O}-1}, d_0, ..., d_{\mathbf{R}-1})

      could be split into a left set of **O** outer dimensions, :math:`\boldsymbol{D}`,
      and a right set of **R** region dimensions, :math:`\boldsymbol{d}`,
      where the data field has a total of **O** + **R** dimensions. Note **O** :math:`>= 0`.

  **O**: Number of outer dimensions

  **R**: Number of region dimensions

  .. _/NXregion/block-field:

  .. index:: block (field)

  **block**: (optional) :ref:`NX_INT <NX_INT>` (Rank: 1, Dimensions: [R]) 

    .. collapse:: An optional field to define the block size used to copy or downsample data. In ...

        An optional field to define the block size used to copy or downsample data. In the
        :math:`i`-th dimension, if :math:`\mathbf{block}[i] < \mathbf{stride}[i]`
        then the downsampling blocks have gaps between them; when ``block`` matches ``stride``
        then the blocks are contiguous; otherwise the blocks overlap.
        If omitted then defined as an array of ones.

  .. _/NXregion/scale-field:

  .. index:: scale (field)

  **scale**: (optional) :ref:`NX_NUMBER <NX_NUMBER>` (Rank: 1, Dimensions: [R]) 

    .. collapse:: An optional field to define a divisor for scaling of reduced data. It is appli ...

        An optional field to define a divisor for scaling of reduced data. It is applied after the
        reduction operation. For example, in a downsampled sum, it can reduce the maximum values to fit
        in the domain of the result data type. In an image that is downsampled by summing 2x2 blocks,
        using :math:`\mathrm{scale}=4` allows the result to fit in the same integer type dataset as
        the parent dataset.
        If omitted then no scaling occurs.

  .. _/NXregion/downsampledNAME-group:

  **downsampled**\ :bolditalic:`NAME`: (optional) :ref:`NXdata` :ref:`⤆ </NXobject/DATA-group>`

    .. collapse:: An optional group containing data copied/downsampled from parent group’s data. ...

        An optional group containing data copied/downsampled from parent group’s data. Its dataset name
        must reflect how the downsampling is done over each block. So it could be a reduction operation
        such as sum, minimum, maximum, mean, mode, median, etc. If downsampling is merely copying each
        block then use "copy" as the name. The resulting field from a reduction operation has shape :math:`(D_0, ..., D_{\mathbf{O}-1}, \mathbf{count}[0], ..., \mathbf{count}[\mathbf{R}-1])`.
        In the copy case, the field has shape :math:`(D_0, ..., D_{\mathbf{O}-1}, \mathbf{block}[0] * \mathbf{count}[0], ..., \mathbf{block}[\mathbf{R}-1] * \mathbf{count}[\mathbf{R}-1])`,
        Where more than one downsample dataset is written (specified with ``@signal``) then add
        ``@auxiliary_signals`` listing the others if they possess the same shape. In situtations where
        the copied dataset's shape differs from other datasets (i.e. ``block`` contains values other than 1),
        this must be placed in another ``NXdata`` class called, says, "downsampled_copy".

        The following figure shows how blocks are used in downsampling:

        .. figure:: region/NXregion-example.png
        	:width: 60%

        	A selection with :math:`\mathbf{start}=2, \mathbf{count}=4, \mathbf{stride}=3, \mathbf{block}=2` from
        	a dataset with shape [13] will result in the ``reduce`` dataset of shape [4] and a ``copy`` dataset of shape [8].

        If the parent group is an :ref:`NXdata`, any axes can be downsampled in the
        same manner as the parent data, therefore those downsampled axes should be
        named accordingly. For ``AXISNAME`` in the parent group, `AXISNAME_maximum`
        is the maximum axis values each block. If only the axis values at each block
        origin is recorded, then it is stored as ``AXISNAME`` (this is equivalent to a
        copy with unit block). Axis attributes should be added too.

  .. _/NXregion/statistics-group:

  **statistics**: (optional) :ref:`NXdata` :ref:`⤆ </NXobject/DATA-group>`

    .. collapse:: An optional group containing any statistics derived from the region in parent  ...

        An optional group containing any statistics derived from the region in parent group’s data
        such as sum, minimum, maximum, mean, mode, median, rms, variance, etc. Where more than one
        statistical dataset is written (specified with ``@signal``) then add ``@auxiliary_signals``

        If the parent group is an :ref:`NXdata`, any axes for the outer dimensions should added
        alongside matching axis attributes.
